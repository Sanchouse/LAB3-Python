# Лабораторная работа 3. Каталог объектов (медиатека)

Пакет `mediacatalog` с предметной моделью медиатеки и каталогом объектов: добавление, поиск, удаление, сохранение в JSON и загрузка из JSON.

## Структура проекта

```
LAB3 Python/
├── pyproject.toml            # настройки pytest (pythonpath = "src")
├── README.md

│       ├── models.py         # dataclass MediaItem и проверка инвариантов
```

## Запуск

Демонстрация (из папки `src`):

```
python -m mediacatalog.demo
```

Демо создаёт объекты прямо в коде, показывает все операции каталога, ловит ожидаемые ошибки, печатает их и продолжает работу. В конце оно создаёт файлы `demo.json`, `bad.json` и `v2.json` в текущей папке (их можно удалить).

Тесты (из корня проекта):

```
pytest
```

Запускать `demo.py` напрямую (`python demo.py`) не нужно: внутри пакета используются импорты вида `from . import errors`, они работают только при запуске как часть пакета.

## Сущность `MediaItem`

Неизменяемый (`frozen=True`) dataclass.

| Поле | Тип | Правило |
|---|---|---|
| `item_id` | `str` | уникальный идентификатор, непустая строка |
| `name` | `str` | название, непустая строка |
| `category` | `str` | категория (например, `music`, `film`), непустая строка |
| `year` | `int` | год выпуска, от 1850 до текущего года |
| `creator` | `str` | автор или исполнитель, непустая строка |
| `duration_minutes` | `int` | длительность в минутах, целое больше 0 |

Инварианты проверяются в `__post_init__`, поэтому неверный объект создать нельзя. При нарушении выбрасывается `IncorrectType`. Значения `bool` не принимаются как числа.

```python
from mediacatalog.models import MediaItem

item = MediaItem("item-7319", "Выздороветь", "music", 2025, "soltwine", 3)
```

## Каталог `Catalog`

| Метод | Описание |
|---|---|
| `add(item) -> None` | добавляет объект; `IncorrectType`, если это не `MediaItem`; `ExistingID` при дубликате ID |
| `get(item_id)` | возвращает объект; `ItemNotFound`, если ID нет |
| `remove(item_id)` | удаляет и возвращает объект; `ItemNotFound`, если ID нет |
| `find_by_category(category)` | список объектов с этой категорией, регистр не важен |
| `find_by_name(query)` | список объектов с этим названием, регистр не важен |
| `save(path)` | сохраняет каталог в JSON |
| `load(path)` | заменяет содержимое каталога данными из JSON |
| `len(catalog)` | количество объектов |
| `for item in catalog` | перебор объектов |
| `item_id in catalog` | проверка наличия ID |

### Принятые решения

- **Хранение.** Объекты лежат в словаре `id -> MediaItem`, поэтому поиск по ID выполняется за O(1).
- **Порядок итерации.** Объекты возвращаются в порядке добавления (словарь Python сохраняет порядок вставки). Порядок детерминирован и не зависит от ID.
- **Поиск.** `find_by_category` и `find_by_name` сравнивают строки через `casefold()` и ищут точное совпадение (без учёта регистра). Результат всегда новый список, внутренняя структура каталога наружу не отдаётся. Итерация тоже идёт по копии, поэтому каталог можно менять во время цикла.
- **Загрузка заменяет содержимое.** `load` не добавляет записи к существующим, а полностью заменяет каталог. Так результат `save` и `load` совпадает (round trip), а конфликтов ID не возникает.
- **Методы не печатают и не завершают программу.** Они только выбрасывают исключения, а решает, что с ними делать, вызывающий код (например, `demo.py`).

## Формат JSON-файла

```json
{
    "format_version": 1,
    "items": [
        {
            "item_id": "item-7319",
            "name": "Выздороветь",
            "category": "music",
            "year": 2025,
            "creator": "soltwine",
            "duration_minutes": 3
        }
    ]
}
```

Ключи объектов совпадают с полями dataclass. Список `items` сохраняет порядок, поэтому после загрузки порядок итерации тот же.

### Защита от частичных изменений

Загрузка выполняется в два шага:

1. `load_from_json` читает файл, проверяет структуру и версию, создаёт и проверяет каждый `MediaItem` и собирает **новый** словарь. Существующий каталог в это время не затрагивается.
2. Только после полного успеха `Catalog.load` одним присваиванием подменяет внутренний словарь.

При любой ошибке (битый JSON, неизвестная версия, невалидная запись, дубликат ID в файле) каталог остаётся прежним.

Сохранение пишет данные во временный файл `.tmp` и затем переименовывает его, поэтому сбой во время записи не портит существующий файл.

## Исключения

Все исключения лежат в `mediacatalog.errors` и наследуются от `CatalogError`.

| Исключение | Когда возникает |
|---|---|
| `CatalogError` | базовый класс |
| `IncorrectType` | неверная сущность: неверный тип или значение поля, в `add` передан не `MediaItem` |
| `ExistingID` | объект с таким ID уже есть в каталоге |
| `ItemNotFound` | объекта с таким ID нет в каталоге |
| `UnsupportedFormatVersion` | `format_version` не поддерживается загрузчиком |
| `CorruptedFile` | файл не читается, не является корректным JSON, имеет неверную структуру, содержит невалидный объект или дубликат ID |

## Тесты

Тесты написаны на pytest и сгруппированы по классам:

- `TestEntity`: допустимая сущность (в том числе с ID `item-7319`) и недопустимые
- `TestAddGetRemove`: добавление, получение, удаление
- `TestDuplicateID`: дубликат ID
- `TestSearch`: поиск по категории и имени, возврат копии
- `TestIteration`: порядок итерации
- `TestJsonRoundTrip`: сохранение и загрузка, `format_version` в файле
- `TestJsonErrors`: повреждённый JSON, неверное содержимое, неподдерживаемая версия
- `TestFailedLoadKeepsCatalog`: каталог не меняется после неудачной загрузки

Данные в тестах задаются прямо в коде, файлы создаются во временных папках (`tmp_path`).
